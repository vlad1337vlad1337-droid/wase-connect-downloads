# Wase Connect — интеграция подписок для провайдеров

Версия контракта: **2.1.0**, 11 октября 2026. Это версия описываемого клиента; нумерация существующих форматов данных не меняется. Импорт использует общий C++-клиент; приёмка сетевого модуля выполняется отдельно для каждой платформы. macOS, Windows и Android имеют внутренние установщики, iPhone/iPad — сборку для симулятора. Наличие импортера или успешная сборка не означает подтверждённое VPN-подключение на устройстве.

Этот документ описывает поведение кода Wase, а не обещание поддержки каждого расширения Xray, sing-box, Clash или стороннего приложения. Примеры содержат вымышленные домены `.example` и демонстрационные ключи. Не отправляйте реальные URL подписок в публичные issue, логи CI или аналитику.

## 1. Рекомендуемый ответ сервера

Самый простой вариант — HTTPS endpoint с текстом, где каждая строка содержит самостоятельную ссылку на сервер. Название, описание, объявление, трафик и ссылки передавайте HTTP-заголовками. Для кириллицы в заголовках используйте `base64:` от UTF-8.

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Cache-Control: private, no-store
profile-title: Wase Secure
profile-description: Reliable private connection
announce: Maintenance: 01:00-01:15 UTC
subscription-userinfo: upload=1073741824; download=2147483648; total=107374182400; expire=1842307200
profile-update-interval: 1
support-url: https://support.provider.example/help
profile-web-page-url: https://provider.example/account

vless://00000000-0000-4000-8000-000000000001@de.provider.example:443?type=tcp&security=tls&sni=de.provider.example#%F0%9F%87%A9%F0%9F%87%AA%20Germany
vless://00000000-0000-4000-8000-000000000002@nl.provider.example:443?type=tcp&security=tls&sni=nl.provider.example#%F0%9F%87%B3%F0%9F%87%B1%20Netherlands
```

UUID и имена здесь учебные. Замените их параметрами действительно настроенных серверов. В примере нет Reality: для него нужны согласованные параметры сервера, публичный ключ, short ID и имя TLS. Не меняйте лишь слово `security`, оставляя остальные параметры от другого транспорта.

Рекомендация для стабильной выдачи: один формат на endpoint; постоянный идентификатор и имя каждой ноды; не менее одной обычной самостоятельной ноды; понятные HTTP-коды для ошибок. Не выдавайте HTML-страницу кабинета вместо конфигурации.

## 2. Запрос клиента и устройства

Общий клиент отправляет следующие заголовки; в примере показан macOS:

| Заголовок | Значение и назначение |
|---|---|
| `User-Agent` | `WaseConnect/2.1.0 (Wase Connect; macOS <версия>; <архитектура>)` |
| `X-App-Name` | `Wase Connect`, удобное имя клиента |
| `X-App-Version` | Версия приложения, например `2.1.0` |
| `X-Device-Os` | `macOS`, `Windows`, `Android` или `iOS` |
| `X-Ver-Os` | Версия системы |
| `X-Device-Model` | На macOS — `Mac (<hw.model>; <чип>)`, при отсутствии сведений — `Mac`; Windows — ОС и архитектура, Android/iOS — значение платформенного адаптера |
| `X-Hwid` | Стабильный для установки и origin SHA-256 идентификатор |
| `Accept` | `application/json, text/plain;q=0.9, */*;q=0.1` |

Названия HTTP-заголовков регистронезависимы. Не определяйте сервис по обрезанному первому слову User-Agent: `X-App-Name` содержит пригодное для интерфейса имя. Для устройства показывайте модель и ОС отдельно от имени клиента.

`X-Hwid` вычисляется из случайного идентификатора установки и origin (`scheme://host:port`). Это **не MAC-адрес, не серийный номер и не аппаратный UUID**. Перезапуск и обычное обновление сохраняют его; удаление данных приложения может изменить. Другой origin получает другой идентификатор, в том числе после редиректа. Провайдер с несколькими доменами должен учитывать это в учёте устройств. Идентификатор не является криптографическим доказательством физического устройства и не заменяет авторизацию подписки.

Wase не передаёт имя пользователя macOS. Серверу не следует требовать имитации Happ/INCY в User-Agent или неизвестного чужого HWID: это ломает корректный учёт клиентов.

## 3. Метаданные и комментарии

| Поле | Предел / формат | Отображение |
|---|---|---|
| `profile-title` | До 120 символов первой строки после декодирования | Название подписки и группы серверов |
| `subscription-name` | Запасной вариант названия | Используется при отсутствии пригодного `profile-title` |
| `profile-description` | До 2048 символов | До двух строк на карточке и в группе серверов; полный текст — в сведениях подписки |
| `announce` | До 4096 символов | Объявление, отдельно от описания |
| `announce-url` | HTTPS, до 4096 символов, без userinfo | Ссылка объявления; открывается только нажатием пользователя |
| `subscription-userinfo` | До 2048 символов | Трафик, остаток, срок |
| `support-url` | HTTPS, до 4096 символов, без userinfo | Поддержка |
| `profile-web-page-url` | HTTPS, до 4096 символов, без userinfo | Личный кабинет |
| `homepage` | Такие же ограничения | Запасной адрес сайта; HTTP metadata приоритетнее body, canonical поле приоритетнее alias в одном источнике |
| `profile-update-interval` | Целое число часов | Рекомендация провайдера; не переопределяет предпочтение пользователя |
| `wase-theme` | До 8 КиБ, строгая схема `wase-theme-v1` | Предложение темы; применение и загрузка фона только после выбора пользователя, см. [формат тем](THEMES.md) |
| `Content-Disposition` | `filename` или `filename*=UTF-8''…` | Запасное название, когда остальных нет |

Текст — plain text. HTML/Markdown, инструкции клиенту, JavaScript и управляющие bidi-символы не исполняются. Ссылки открываются только по действию пользователя. `tg://`, `javascript:`, HTTP и URL с логином/паролем для кнопок поддержки не принимаются; используйте `https://t.me/...`.

Название, описание и объявление могут быть `base64:<UTF-8-base64>`. Например, Python:

```python
import base64
value = 'Надёжное подключение. Вопросы — в поддержку.'
header = 'base64:' + base64.b64encode(value.encode('utf-8')).decode('ascii')
```

В текстовом формате допустимы комментарии:

```text
# profile-title: Example Connect
# profile-description: Support and information about the subscription
# announce: New locations are available
# subscription-userinfo: upload=0; download=0; total=0; expire=0
# support-url: https://support.provider.example/help
# profile-web-page-url: https://provider.example/account
# profile-update-interval: 1
vless://00000000-0000-4000-8000-000000000001@de.provider.example:443?security=tls&type=tcp&sni=de.provider.example#Germany
```

HTTP-заголовки имеют приоритет над одноимёнными комментариями. HTTP-алиасы названия проверяются раньше алиасов тела. Первое пригодное значение комментария побеждает повторное. Если название многострочное и отдельного описания нет, последующие строки становятся описанием. Пользовательское переименование подписки сохраняется при обновлении.

В JSON не добавляйте строки-комментарии перед объектом: используйте HTTP-заголовки. Произвольные поля JSON вроде `description` не считаются универсальным эквивалентом этих заголовков. Служебные ноды с названиями «осталось N ГБ» — ненадёжный способ передавать сведения; используйте метаданные.

Описание и объявление отображаются как на карточке подписки, так и в её группе на экране выбора сервера. В 2.1.0 описание в этих списках сокращено до двух строк; полный текст доступен через сведения подписки. Совпадающие описание и объявление не требуется дублировать. Сворачивание группы скрывает её содержимое, не удаляя подписку.

## 4. Трафик, срок и безлимит

`subscription-userinfo` содержит пары через точку с запятой:

```text
upload=1024; download=2048; total=107374182400; expire=1842307200
```

- `upload`, `download`, `total` — неотрицательные целые **байты**, не МБ/ГБ и не отформатированный текст.
- `expire` — Unix-время в **секундах**. Распознаваемые большие значения в миллисекундах приводятся к секундам; отправляйте секунды для однозначности.
- Использовано = upload + download. Остаток не опускается ниже нуля.
- Явное `total=0` означает безлимит. Отсутствующее `total` означает неизвестный лимит, а не безлимит.
- `expire=0`/отсутствующее поле не создаёт вымышленной даты окончания.
- Принимаются точно представимые целые до `9007199254740991`; отрицательные числа, дроби, `NaN` и текст единиц измерения не принимаются.
- Истёкшая подписка не подменяется обещанием активного доступа. Фактическая авторизация остаётся обязанностью сервера.

Не увеличивайте счётчики только при запросе конфигурации: это статистика трафика пользователя. Если данных нет, не выдавайте произвольные нули. Показываемые значения актуальны на последнее успешное получение метаданных.

## 5. HTTPS, редиректы и ошибки

Удалённая подписка — HTTPS URL без `user:password@host`. Для локальных регрессионных стендов разрешён loopback HTTP; это не рекомендация публичному провайдеру. Ссылка может содержать секретный токен в пути/query; относитесь ко всей ссылке как к паролю.

- Предел тела — 8 МиБ; таймаут получения — 25 секунд.
- До пяти HTTPS-редиректов, без перехода на незашифрованный HTTP; заголовки устройства пересчитываются для нового origin.
- Сертификат должен проходить системную проверку. Self-signed, неверное имя или истёкший сертификат не исправляются отключением проверки TLS.
- Wase запрашивает актуальные данные без браузерного cache. Контракт условного `ETag`/`304 Not Modified` пока не реализован: возвращайте полное тело `200 OK`.
- Не требуйте браузерные cookies, CAPTCHA, JavaScript challenge или ручное прохождение страницы входа у машинного endpoint.
- Используйте `401/403` для отсутствия доступа, `429` для rate limit, `5xx` для временной ошибки. Не возвращайте страницу ошибки с `200`.

Если обновление не содержит ни одной пригодной ноды, прежний рабочий набор сохраняется. При частично поддержанном ответе импортируются допустимые записи; отклонённые не превращаются молча в другой транспорт. У новой неуспешной подписки остаётся ошибка, чтобы пользователь мог исправить ссылку/повторить запрос. Пустой список в кабинете не доказывает, что клиент успешно импортировал ответ.

Не записывайте полный URL или тело запроса в обычный access log. Не включайте секретный токен в сообщения об ошибках, `profile-title` или объявления.

## 6. Форматы входа

| Формат | Что используется | Ограничения |
|---|---|---|
| Текстовый список URI | Самостоятельные ссылки по строкам | UTF-8, поддерживаемые схемы |
| Base64 | Текст/поддерживаемый JSON/YAML; обычный и URL-safe вариант | Не шифрование, не защита секрета |
| Xray JSON | Поддерживаемые outbounds, отдельные конфигурации/массив | Не произвольные цепочки/DNS/inbounds; ограниченная маршрутизация предлагается отдельно, см. раздел 12 |
| sing-box JSON | Поддерживаемые outbounds/endpoints | Группы selector/urltest сами не являются физическими серверами |
| Clash/Mihomo YAML и JSON | Встроенный `proxies`, отдельные именованные ноды и массивы, inline `proxy-providers.payload` | Внешний граф proxy-providers не загружается; строгий ограниченный YAML |
| WireGuard / AmneziaWG `.conf` | Interface/Device и Peer | Применимы протокольные ограничения ниже |
| Локальный файл/вставленный профиль | Отдельная группа | Нет сетевого автообновления |

Суммарно хранилище допускает 2000 серверов. YAML с дублирующимися ключами, произвольными тегами/циклическими ссылками отклоняется. Превышение лимита — причина явной ошибки, а не обещание импортировать весь ответ.

Формат приложения не равен формату подписки. Экспорт большого клиента может включать правила, плагины, сертификаты с путями, selectors, локальные listen-порты и служебные entries: не все они являются серверами. Число строк или JSON-объектов не обязано совпадать с числом карточек.

Inline provider имеет вид `{"proxy-providers":{"Example":{"type":"inline","payload":[<объект Clash-ноды>]}}}`. Это уже включённые в ответ данные. `type: http` с URL, `type: file` с путём и другие внешние источники не открываются; для добавления серверов выдайте прямую HTTPS-подписку либо встроенные proxies. Получение внешних rule-providers также не выполняется автоматически.

## 7. Протоколы и транспорты

| Протокол | Вход | Особенности |
|---|---|---|
| VLESS | URI, Xray/sing-box JSON, поддерживаемый Clash | TCP, TLS/Reality, WS, gRPC, HTTPUpgrade, XHTTP в поддерживаемых сочетаниях; XHTTP через Xray |
| VMess | URI/share JSON, JSON/YAML | Совместимые настройки шифрования/транспорта |
| Trojan | URI, JSON/YAML | Корректный пароль, TLS и SNI |
| Shadowsocks / 2022 | URI, JSON/YAML | Поддерживаемые cipher/key; произвольные исполняемые plugins не запускаются |
| SOCKS | URI, JSON/YAML | Не делает сам по себе канал шифрованным |
| HTTP/HTTPS proxy | URI с явным портом, JSON/YAML | Анонимный proxy задавайте конфигурацией; HTTPS требует проверяемый TLS |
| Hysteria 2 | URI, sing-box/Clash; поддерживаемый Xray HY2 | UDP, корректная аутентификация/TLS; pin сохраняется в поддерживаемой схеме |
| Hysteria 1 | `hysteria://` / `hy://`, sing-box JSON | Требует bandwidth-параметры; Clash HY1 не поддержан |
| TUIC v5 | URI, sing-box JSON, Clash | TUIC v4 не поддержан |
| AnyTLS | URI, sing-box JSON, Clash | TLS не отключается для удобства импорта |
| WireGuard | `.conf`, `wg://` / `wireguard://`, sing endpoint/старый outbound, Xray/Clash | До 32 peers; ключи проверяются |
| AmneziaWG 1/2/3.1 | `.conf`, `awg://` / `amneziawg://`, поддерживаемые JSON-контейнеры | Один peer на профиль; сохраняются J/S/H/I; официальный движок AWG |

Неподдерживаемые семейства: **OpenVPN, IKEv2/IPsec, SSTP, ShadowsocksR, TUIC v4**. Не реализованы закрытые зашифрованные контейнеры Amnezia `vpn://` и Happ crypto, произвольные outbound-цепочки, все экспериментальные параметры любого внешнего ядра. Не рекламируйте «абсолютно любые подписки».

`TCP`, `TLS`, `Reality`, `HTTP`/`XHTTP` — разные уровни описания соединения. Список стран и значок флага не определяют транспорт. Сверяйте конфигурацию с конкретным ядром и серверной версией. Текущие версии: sing-box 1.14.2-wase.3 с адаптером AWG и исправлением прямых IPv6-соединений; Xray 26.9.30 (предварительный выпуск upstream).

В 1.6.8 исправлены дополнительные преобразования: Clash VLESS XHTTP/TLS/Reality в пределах поддерживаемых полей; WebSocket headers и `?ed=` early data; Reality `spiderX` / `spx` через Xray для TCP/gRPC/XHTTP. Неподдерживаемые gRPC `authority` / `multiMode` у VMess/Trojan, неизвестный TCP `headerType` и непереносимое `udp: false` отклоняются вместо удаления значимых параметров.

### TLS-отпечаток, имя сервера и сертификаты

Отпечаток задаётся **для конкретной ноды**, а не является обязательным свойством всей подписки. Поддерживаемые форматы передают его как `fp` в URI, `fp` в VMess share JSON, `tlsSettings.fingerprint` / `realitySettings.fingerprint` в Xray, `tls.utls.fingerprint` в sing-box и `client-fingerprint` в Clash. В sing-box также требуется `utls.enabled: true`.

В профессиональных настройках Wase режим **«Из подписки»** сохраняет импортированное значение и является стандартным. Пользователь может явно выбрать другой совместимый пресет для следующего подключения; это не переписывает URL, ключи и исходный профиль. Обычные названия доступных пресетов: `chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `360`, `qq`, `random`, `randomized`. `random` выбирает браузерный пресет; `randomized` создаёт синтетический ClientHello. Они не означают автоматическую проверку всех браузеров и выбор работающего обхода.

Для Reality требуется TLS 1.3. В закреплённых ядрах обычные пресеты `android` и `360` её не предлагают: такая явная комбинация в подписке отклоняется. Если пользователь выбрал Android или 360 глобально, параметры Reality-узла сохраняются; эти варианты применяются только к подходящим обычным TLS-соединениям. Версионный Xray `Hello360_11_0` отличается от короткого `360` и предлагает TLS 1.3. Не определяйте совместимость по одному названию семейства браузера.

Нативные Xray `Hello*` распознаются только там, где узел действительно выполняется Xray: поддерживаемые VLESS TCP/raw, gRPC и XHTTP. Для Reality принимаются проверенные современные версии из встроенного ядра; старые или случайно генерируемые нативные варианты без гарантированной TLS 1.3 отклоняются. В sing-box такие нативные имена не заменяются ближайшим пресетом.

`server_name`/`sni`, публичный ключ и short ID Reality, ALPN и сертификаты должны соответствовать серверу провайдера. Смена отпечатка не исправляет неверные значения этих полей. Профили TCP TLS и QUIC имеют разные возможности; глобальный выбор браузерного отпечатка не должен добавлять uTLS в WireGuard, AmneziaWG, Hysteria, TUIC или незашифрованное соединение. Не заменяйте неизвестное имя пресета на `chrome` молча.

В закреплённых ядрах нет отдельного подтверждённого пресета Яндекс Браузера или Атома. Значение `yandex` не означает Chrome и не является поддерживаемым именем. Поддержка российских удостоверяющих центров в браузере относится к проверке сертификата сайта, а uTLS меняет ClientHello соединения **к VPN-серверу**. При обычном туннелировании сертификат посещаемого сайта проверяет приложение пользователя. Wase не устанавливает корневые сертификаты в систему и не отключает проверку TLS при выборе отпечатка.

Официальные описания: [TLS в Xray](https://xtls.github.io/en/config/transports/tls.html), [TLS в sing-box](https://sing-box.sagernet.org/configuration/shared/tls/), [поддержка сертификатов Яндекс Браузером](https://yandex.ru/project/browser/sert/1). Успешная проверка конфигурации не подтверждает доступность узла в конкретном белом списке оператора; для этого нужен реальный сетевой тест.

### Личные настройки отдельной ноды

В карточке сервера можно открыть настройки подключения, изменить обычные поля либо JSON **одного соединения**, выбрать собственный совместимый TLS-отпечаток. В 1.6.10 вкладки показывают параметры и JSON; отдельно доступны исходник подписки и применяемая конфигурация ноды после TLS-переопределения. Редактируемый JSON — нормализованное представление рабочего движка sing-box либо Xray. Исходный объект Xray/sing-box/Mihomo/VMess сохраняется отдельно для чтения (128 КиБ на ноду, 4 МиБ на хранилище); он не исполняется вместо нормализованного объекта. Старые записи получают исходник при очередном успешном обновлении JSON-подписки; URI и записи без сохранённого оригинала показывают преобразованную конфигурацию с отдельным названием. Допустимы только поля, поддерживаемые соответствующим импортёром и протоколом. Неверный JSON, несовместимый отпечаток, полная конфигурация с inbounds/DNS/маршрутами и неизвестные опасные поля не сохраняются. Предел текста — 128 KiB.

Изменения локальные: клиент не изменяет подписку на сервере провайдера и не отправляет отредактированный JSON назад. Оригинал провайдера хранится отдельно. При сохранении записывается разница между оригиналом и личным вариантом; при обновлении она накладывается на свежий оригинал. Объекты объединяются по полям, удаление задаётся `null` в patch; **массивы заменяются целиком**. Например, редактирование одного элемента `vnext` закрепляет весь этот массив: обновившиеся адреса или ключи внутри него не заменят личный массив автоматически. Это свойство merge patch, а не обещание независимо объединять каждую строку.

Приоритет отпечатка: личный выбор ноды → общий выбор приложения → значение исходной/отредактированной конфигурации. Выбор «Из JSON ноды» сохраняет собственное значение редактируемой конфигурации, обходя общий override; наследование настроек приложения использует общий режим. Сброс возвращает ноду к актуальной конфигурации провайдера и общим предпочтениям.

При обновлении личные параметры связываются только в пределах той же подписки: по неизменившейся ссылке или однозначной паре имени и протокола. Два сервера с одинаковым названием не получают чужие параметры по случайному совпадению. Исчезнувшая/неоднозначная отредактированная нода сохраняется отдельно и требует проверки перед подключением; несовместимая смена формата также блокирует её использование. Если подписка обновилась, пока редактор открыт, устаревшая форма не перезаписывает новые параметры — нужно загрузить актуальную конфигурацию.

Редактировать и сбрасывать настройки подключения можно после отключения VPN. Сохранение само по себе не проверяет доступность внешнего сервера: после изменения нужны повторное подключение и функциональная проверка требуемых сервисов.

## 8. Минимальные примеры альтернативных форматов

### sing-box: один VLESS TLS

```json
{"outbounds":[{"type":"vless","tag":"🇩🇪 Germany","server":"de.provider.example","server_port":443,"uuid":"00000000-0000-4000-8000-000000000001","tls":{"enabled":true,"server_name":"de.provider.example"}}]}
```

### Clash: встроенная нода

```yaml
proxies:
  - name: "🇳🇱 Netherlands"
    type: vless
    server: nl.provider.example
    port: 443
    uuid: 00000000-0000-4000-8000-000000000002
    tls: true
    servername: nl.provider.example
    network: tcp
```

### WireGuard

```ini
[Interface]
PrivateKey = <base64-ключ, 32 байта после декодирования>
Address = 10.20.0.2/32

[Peer]
PublicKey = <base64-ключ сервера, 32 байта после декодирования>
Endpoint = wg.provider.example:51820
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25
```

Последний пример — шаблон, а не валидный профиль: замените угловые placeholders реальными ключами. Включение `DNS=` в `.conf` не переопределяет политику DNS Wase. Для AmneziaWG добавляются действительные согласованные поля выбранного поколения; нельзя использовать вымышленные значения ради «совместимости».

## 9. Имена, флаги и автоматический выбор

Флаг берётся из известных названий/кодов стран и emoji-флагов в имени провайдера. Wase использует локальные SVG-ассеты; это не геолокация выходного IP и не гарантия нахождения железа в указанной стране. Для надёжного отображения используйте `🇩🇪 Germany`, `🇳🇱 Netherlands`, `🇫🇮 Finland` и аналогичные однозначные названия. Не смешивайте несколько стран без объяснения. Непонятная страна получает общий значок, а не случайный флаг Германии.

Автоматический выбор Wase рассматривает самостоятельные обычные ноды прежде резервов обхода/белых списков. Медийные «Россия прямая» не являются обычным иностранным выходом. Имена, явно означающие чужой автоагрегатор (`Автовыбор`, `Автоподбор`, `auto`, `urltest`, `fallback` и подобные), исключаются из автоматического выбора Wase, но остаются доступны вручную. Эвристика зависит от имени; отдельного универсального HTTP-поля `priority` или `node-role` в этом контракте нет.

Не используйте слово «Автовыбор» для обычного стабильного сервера, который должен участвовать в автоматике клиента. Не выдавайте рекламные сообщения как авторизованные VPN-ноды. Если профиль — реальный каскад или балансировщик, проверьте поддержку его структуры отдельно.

При нескольких подписках группы сохраняют названия, свои действия обновления, измерения, избранного и сворачивания. Одинаковые страны из разных подписок не теряют принадлежность провайдеру. Дубликаты структурированных выходов в одном импорте могут схлопываться; служебные direct/block/DNS/selector не становятся отдельными удалёнными нодами.

## 10. Обновление и активное соединение

По умолчанию интервал — **1 час**. Таймер проверяет срок раз в минуту, при запуске и после возобновления работы. Это не внешняя серверная cron-задача и не гарантированный вызов в ту же секунду каждый час.

- Пока приложение работает, обновление идёт без открытия экрана подписок.
- После полного выхода из приложения обновления нет. Сон/энергосбережение могут отложить проверку до пробуждения.
- Учитываются время последнего успешного обновления и последней попытки. Неудача не запускает бесконечный частый цикл запросов.
- Во время активного подключения новые ноды сохраняются как ожидающее изменение. Текущий процесс и маршрут не перезапускаются только из-за обновления; новый набор применяется при освобождении сессии/следующем запуске.
- Метаданные могут обновиться раньше самого активного профиля. Это нормальное различие: квота относится к аккаунту, а работающий туннель использует уже загруженный конфиг.
- Ротация/отзыв ключа на стороне провайдера может оборвать текущую серверную сессию независимо от клиентского таймера.
- Ручное «Обновить» обновляет подписку, а отдельный «Пинг» измеряет ноды. Это разные действия.
- Доступные пользовательские интервалы: вручную, 1/3/6/24 часа. Заголовок рекомендации провайдера не принуждает клиента к иному режиму.

## 11. Пинг и проверка соединения

Цифра TCP RTT — время установления TCP-соединения **с устройства до host:port ноды**, без HTTP-запроса к Google/Cloudflare. DNS-разрешение имени не включается. На macOS сокет привязывается к физическому интерфейсу; измерение вынесено из графического потока, чтобы анимации/прокрутка не завышали время.

Обычно выполняются до 16 измерений одновременно, таймаут 4 секунды. При входе в список/автоподборе используется ограниченный набор до 32 кандидатов и кеш, а не тысяча запросов сразу. Полный замер запускается для конкретной подписки. Текущая прокрутка и уже известные цифры сохраняются.

UDP-протоколам WG/AWG/Hysteria/TUIC не приписывается вымышленный TCP-пинг. Отсутствие TCP-цифры не означает отказ UDP-сервера. Доступный TCP-порт не подтверждает VPN-аутентификацию, DNS, скорость видео, Discord UDP или отсутствие фильтрации. Перед сообщением о подключении Wase отдельно проверяет реальный маршрут через ядро.

Сравнивая с другими клиентами, проверьте одинаковые адрес, порт, сеть, транспорт, момент измерения и включённые другие VPN. Медиана ICMP, HTTP до контрольного сайта и TCP handshake — разные величины. Даже два TCP-измерения могут различаться из-за потерь/ретрансляций.

## 12. DNS, маршруты и страны эксплуатации

Wase использует собственные шаблоны конфигурации. Импорт серверов не исполняет целиком чужие DNS/inbounds/routing. Правила провайдера распознаются отдельно и доступны в сведениях подписки. В текущем клиенте умная маршрутизация включена по умолчанию в режиме **Автоматически**: используется полностью поддерживаемый профиль подписки фактического выбранного сервера, иначе правила Wase. Сохранённое пользователем выключение сохраняется после обновления; общий переключатель отключает также профиль провайдера.

### Политика провайдера и GeoSite

Принимаемые каналы: HTTP-заголовок `routing` с `happ://routing/add/<base64>` или `happ://routing/onadd/<base64>`; такая же строка в обычном/Base64 теле либо `# routing: ...`; `routing.rules` полного Xray JSON; `route.rules` sing-box JSON; `rules` Mihomo/Clash JSON/YAML. Это данные подписки, а не автоматическое выполнение чужой команды `onadd`. Самостоятельный Happ-профиль без VPN-нод не является подпиской доступа.

Ограниченный перенос поддерживает точный домен, суффикс домена, публичный IP/CIDR и явно разрешённые встроенные GeoSite-категории; назначения — напрямую, выбранное VPN-подключение или блокировка. Правила DNS для доменов согласуются с назначением: direct → локальный resolver, VPN → resolver через VPN. Чужой список DNS, `DnsHosts`, FakeDNS и установки сертификатов не переносятся. Предупреждение «DNS провайдера не применяется» означает перенос только поддерживаемых маршрутов, а не эквивалентность полной конфигурации.

Режим выбирается в **Маршрутизация → Профиль маршрутизации**:

- **Автоматически**: профиль определяется по стабильному ID подписки фактической ноды, включая измеренного или резервного кандидата. Нет профиля, он неполон/неподдерживаем или отсутствует нужная встроенная база — используется Wase; краткая причина видна в маршрутизации, полный отчёт — в сведениях подписки.
- **Wase**: используются встроенные правила и настройки пользователя.
- **Закреплённый профиль провайдера**: пользователь сохраняет проверенный снимок для **всех подключений Wase**, включая другие подписки. Прежние явно применённые профили мигрируют в этот режим.

Порядок: перехват DNS, LAN/local names и собственные bypass-домены; явно выбранные пользователем игровые/региональные приоритеты; правила провайдера; оставшиеся правила Wase. Это не разрешает провайдеру заменять локальный resolver, слушатели или управление ядром. Одновременно действует один снимок. Имя конкретного чужого удалённого outbound не превращается автоматически в Wase: для Xray/sing-box такое отображение допустимо только с одним самостоятельным удалённым outbound. Произвольные группы, цепочки и несколько различных политик внутри массива не объединяются.

Сеанс фиксирует эффективный профиль до построения конфигурации. Обновление подписки или выбора профиля не переписывает правила работающего ядра: Auto берёт обновление для следующего сеанса, закреплённый профиль сохраняет утверждённый снимок до нового выбора пользователя. Переход к кандидату с другими правилами требует контролируемого переподключения; selector PUT применяется только при одинаковой идентичности правил. При неудачном ручном переходе допускается одна попытка вернуть прежнюю проверенную ноду с её замороженным профилем, если ручные настройки не изменились. Остановка отменяет продолжение; изменение общего OFF во время перезапуска учитывается перед новой конфигурацией. Удаление подписки-источника или замена URL очищают закреплённый снимок, переименование — нет.

GeoSite/GeoIP `.dat`, sing-box `.srs`/JSON и Mihomo rule-provider — разные форматы. Внешние `Geositeurl`/`Geoipurl`, удалённые или файловые rule-set и rule-provider определяются как зависимости и показываются в отчёте, но **не скачиваются и не активируются**. Совпадение названия категории с локальной базой не доказывает равенство содержимого. Неизвестная база, условие, неоднозначность или неподдерживаемое действие оставляют всю политику доступной только для просмотра; частичное применение без уведомления не выполняется.

Лимиты нормализованной политики — 512 правил, 4096 элементов, 64 источника/зависимости. Базовые локальные/служебные сети и catch-all через произвольные CIDR не принимаются. Снимок повторно валидируется при подключении. Отсутствующая встроенная база исключает профиль целиком: выбирается Wase с причиной `missing-rules`, а не частичный набор правил. Ошибка применения уже разрешённого снимка останавливает подготовку подключения.

Минимальный Happ-профиль для предложения правил (Base64-encode UTF-8 JSON и передайте ссылку вместе с VPN-нодами):

```json
{"Name":"Example routes","GlobalProxy":true,"DomainStrategy":"AsIs","FakeDNS":false,"DirectSites":["domain:example.com"],"ProxySites":["full:remote.example.net"],"BlockSites":["domain:ads.example.org"]}
```

Списки примера не пересекаются. Действительные домены замените намеренно: прямое назначение раскрывает домашний IP целевому сервису, а прокси-назначение использует выбранный VPN.

При автоматическом DNS клиент проверяет DoH/DoT через маршрут, выбирает корректно ответивший резолвер и кратковременно кеширует результат для ноды/физической сети/режима DNS/идентичности эффективного профиля маршрутизации. Ошибка проверки инвалидирует кеш. Контроль DNS не является TCP-пингом.

Начальные русскоязычные пресеты позволяют прямой доступ к российским/китайским сервисам; смена языка не переписывает сохранённые предпочтения. Домашний IP остаётся IP реального провайдера. Китайские сервисы не имеют универсального требования российского IP. Политика не гарантирует обход всех блокировок России/Китая: пригодность транспорта зависит от оператора, адреса сервера, конфигурации, времени и ограничений сервисов.

Системный прокси macOS охватывает только приложения, использующие его. Полный туннель требует системной службы и разрешения администратора. В текущей локальной macOS-сборке это launchd/TUN/PF, а не Apple NetworkExtension; записи Wase в системном списке VPN не будет. Kill Switch выключен по умолчанию и не реализуется простым HTTP-прокси.

## 13. Deep links и ссылки добавления

При вставке Wase умеет извлекать исходную ссылку из некоторых оболочек `waseworm://import/`, `happ://add/`, `happ://add-sub/`, `streisand://import/`, `v2raytun://import/`, `hiddify://import/`, `hiddify-next://import/`, `incy://import/`, `incy://add/` и известных query-вариантов. Это обработка текста, а не присвоение Wase чужих системных URL-схем.

Для собственного сайта предпочтительны обычная HTTPS-ссылка и явная кнопка копирования; проверенную зарегистрированную схему Wase используйте только после теста конкретного пакета. Не утверждайте, что любая оболочка откроет Wase, если её в системе обслуживает другой клиент. Зашифрованный контейнер и URL-оболочка — разные вещи.

Внутренние `wase-profile://` представления не являются рекомендуемым публичным контрактом провайдера. Публикуйте стандартный URI/JSON/YAML/конфигурацию и метаданные выше.

## 14. Проверка провайдером перед выпуском

1. Создайте отдельный тестовый аккаунт с отзывным токеном. Не используйте административный ключ.
2. Убедитесь, что endpoint отвечает без браузера, с валидным TLS и правильным Content-Type.
3. Проверьте название, многострочное описание, announce, поддержку, кабинет, безлимит/лимит/истечение.
4. Импортируйте 2 подписки, обновите одну. Убедитесь, что её избранное, название и вторая группа не теряются.
5. Проверьте транспорт каждого типа: успешный импорт, проверка конфига ядром, действительное прохождение TCP/UDP там, где требуется.
6. Протестируйте ошибки 403/429/500, HTML вместо тела, некорректный сертификат, редирект, дубликаты, неполный/слишком большой ответ. Рабочий набор не должен исчезать при общей ошибке обновления.
7. Во время активного соединения обновите профиль. Убедитесь, что фоновой перезагрузки туннеля нет; затем переподключитесь и проверьте новый ключ.
8. Проверьте независимые сети (домашний Wi-Fi и мобильный оператор), IPv4/IPv6, сон/пробуждение. Не считайте localhost-тест доказательством работы у каждого оператора.
9. Если выдаёте политику маршрутизации, убедитесь, что она видна отдельно от нод; проверьте Auto, явный Wase и закрепление профиля, DNS/LAN/пользовательские исключения и отмену. Обновите правила: текущий сеанс сохраняет снимок; Auto получает новую версию при следующем подключении, закреплённый профиль требует нового выбора.
10. Отредактируйте ноду и обновите её оригинал: личная разница сохраняется, неотредактированные поля обновляются. Отдельно проверьте изменённые массивы, совпадающие имена, удаление ноды, смену движка и открытую устаревшую форму.

Не запускайте собственные проверки полного туннеля одновременно с другим VPN без согласованного тестового сценария.

## 15. Диагностика типичных проблем

| Симптом | Что проверить |
|---|---|
| «Модель не сообщает» в кабинете | Обработку `X-Device-Model`, а не только User-Agent; регистр имён заголовков |
| Название выглядит как `waseconnect` | Отображайте `X-App-Name`; разделяйте сервис, ОС и модель |
| Комментарий отсутствует | Правильное имя заголовка, UTF-8/base64, отсутствие HTML; не произвольный JSON field |
| Безлимит не указан | Явное `total=0`; отсутствие total не трактуется как безлимит |
| Дата неверна | Unix-секунды, а не строка даты/локальное время |
| Серверов меньше, чем объектов JSON | Служебные выходы, дедупликация, неподдерживаемые поля, ошибка отдельного профиля |
| Новая подписка пустая | HTTPS endpoint, статус, формат, лимиты, ошибка TLS; прежний ошибочный alias |
| Неверный флаг | Имя/emoji страны в ноде; это не GeoIP-верификация |
| Нет TCP-пинга у WireGuard | Протокол UDP; это ожидаемо |
| TCP малый, а подключение не работает | VPN credentials, SNI/Reality, DNS/маршрут/фильтрация после TCP handshake |
| Нода «Автовыбор» не выбирается автоматически | Она исключена как агрегатор провайдера; ручной выбор остаётся |
| Данные не меняются после закрытия приложения | Клиентский таймер работает только в запущенном процессе |
| Серверная ротация обрывает сессию | Срок жизни/отзыв ключа на сервере; staging клиента не отменяет серверный отзыв |

Передавая отчёт, укажите версию приложения, ОС, формат, тип транспорта, обезличенное имя ноды, момент и этап ошибки. Замените UUID, пароли, приватные ключи, токены URL и авторизацию заглушками. Не удаляйте сами имена полей/транспорт — иначе воспроизведение станет невозможным.

Перед публичным распространением необходимо оформить лицензию приложения и исполнить условия зависимостей; их исходники/изменения, notices и рецепты сборки не заменяются «защитой DMG».

## Платформы и границы приёмки 2.1.0

macOS, Windows, Android и iOS/iPadOS собирают общие C++-импортёры и Qt Quick интерфейс. Windows включает отдельные sing-box и Xray; Android и iOS — оба движка в закреплённой мобильной библиотеке. Поддерживаемые XHTTP/Xray-профили не ограничены macOS на уровне реализации, но успешный импорт и наличие движка не доказывают сетевую работоспособность конкретного пакета или устройства.

## Совместимость gRPC URI — 1.6.11

VLESS `type=grpc` (также `type=gun`) сохраняет `serviceName`, `authority`, `mode=multi` и `multiMode=true/1`. Непустой authority или multi-mode используют встроенный Xray bridge; обычный single-stream gRPC остаётся на native sing-box. Противоречивые mode/multiMode, неизвестный режим и управляющие символы в authority отклоняются. Применённый Firefox или иной поддерживаемый fingerprint сохраняется.

Непустые URI-поля `pqv`, `ech`, `vcn`, `pcs`, `fm` пока не реализованы сквозным образом. Они дают явную ошибку с названием параметра вместо импорта с молчаливой потерей требований сервера. В смешанном ответе остальные поддерживаемые ноды продолжают импортироваться. Это не заявление о поддержке всех опций новых версий Xray.

WASE Protocol 0.3 — отдельный лабораторный TLS 1.2 CONNECT-профиль; он не является новой схемой подписки и не изменяет версии TLS чужих протоколов.
